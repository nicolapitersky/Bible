Complete governance framework for AI-assisted software development

The Bible is a binding contract for every AI agent that touches your projects.

AI agents are amnesiac, powerful, and capable of expensive mistakes. Without a structured contract that every agent reads before writing code, teams get inconsistency, security incidents, wrong-environment writes, and compounding technical debt. The Bible is that contract.

It is not a style guide. It is not optional. It is the single source of truth governing Claude Code, Cursor, Codex, Windsurf, Firebase Studio, and any other AI agent across your delivery pipeline.

The Architecture: Two Layers

Inheritance flows one way: Public Bible to Project Bible. Learnings flow back only after anonymisation and human review.

Layer 1: Public Bible (`nicolapitersky/Bible`)

Universal, public, and anonymised. Holds principles, patterns, templates, and scripts that apply to any project. Contains zero project-specific data and is maintained through automated monthly updates and quarterly manual reviews.

Layer 2: Project Bible (inside each project repo)

Generated by Bootstrap or Retrofit. Includes project-specific manifests, architecture decisions, learning pipeline files, project `AGENTS.md`, and IDE rules. This is where real environment IDs and operational details live.

The Core Files and What Each Does

The handbook is split into orchestrators, governance laws, templates, stack addendums, and executable tooling.

  • `BOOTSTRAP.md` - master orchestrator prompt for new projects across six phases.
  • `RETROFIT.md` - audit-first adoption for existing projects, with debt and migration plans.
  • `PRINCIPLES.md` - 12 non-negotiable engineering laws.
  • `AGENTS_TEMPLATE.md` - project-level constitution template with safety, quality, and execution rules.
  • `TWO_BIBLE_MODEL.md` - architecture and anonymised learning flow between layers.
  • `MULTI_AGENT.md` - parallel agent ownership, handoff report format, and merge protocol.
  • `DESIGN_SYSTEM.md` - token-first design system rules; no hardcoded values.
  • `HANDBOOK_UPDATE.md` - monthly automation and quarterly review process.
  • `stacks/` - stack-specific addendums that extend core governance rules.
  • `scripts/` - bootstrap, retrofit audit, env verification, token generation, quality checks.
  • `configs/` - baseline configs and runtime enforcement hooks.
  • `examples/` - reference implementations for Astro and Next.js + Firebase + Stripe.

The Two Governance Layers (Critical Distinction)

`AGENTS.md` is the instruction layer. Security-critical controls also require an enforcement layer: `.claude/hooks/`, `.claude/settings.json`, and task-level constraints. Instructions without enforcement can be bypassed by context loss or prompt injection.

Scratchpad / Learning Pipeline

Daily work -> `/scratchpad:learn` -> `docs/scratchpad/` raw notes -> `/scratchpad:summary` -> `DAILY.md` -> `/scratchpad:export` -> anonymised `EXPORT.md` -> `/bible:update` pull request to Public Bible.
