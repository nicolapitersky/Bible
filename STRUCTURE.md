# STRUCTURE.md — Canonical Folder Structures

> These are the approved folder structures for each stack.
> The bootstrap agent generates the project structure from here.
> Do not deviate from these structures without creating an ADR.

---

## Universal Rules (All Stacks)

Every project, regardless of stack, has these at the root:

```
.env.manifest              ← Environment identifiers (committed, no secrets)
.env.example               ← Secret template (committed, empty values)
.gitignore                 ← Must include .env, service account keys
AGENTS.md                  ← Agent constitution (generated by bootstrap)
README.md                  ← Human-readable setup guide
design-tokens/
  tokens.json              ← Master design token file
  tokens.css               ← Web: CSS custom properties (generated)
  theme.dart               ← Flutter: ThemeData (generated)
  README.md                ← Token usage guide for this stack
docs/
  adr/                     ← Architecture Decision Records
    ADR-000-template.md
    ADR-001-*.md
  TECH_DEBT.md             ← Tech debt log
  TOOL_REGISTRY.md         ← Project-specific approved tools
  QUALITY_CHECKLIST.md     ← Weekly quality run checklist
scripts/
  verify-env.js            ← Environment manifest verification
  seed.js                  ← Database seeding (dev/staging only)
```

### Key Next.js Rules
- App Router only for new projects (not Pages Router)
- Every route group has a clear purpose (marketing vs app)
- `src/lib/env.ts` validates ALL environment variables at startup with Zod
- API routes are in `src/app/api/` — never mixed with page routes
- Server-only code (firebase-admin, stripe server SDK) never imported in client components
- Use `'use client'` and `'use server'` directives explicitly

### `src/lib/env.ts` Pattern (mandatory)
```typescript
import { z } from 'zod';

const envSchema = z.object({
  NODE_ENV: z.enum(['development', 'staging', 'production', 'test']),
  NEXT_PUBLIC_FIREBASE_PROJECT_ID: z.string().min(1),
  FIREBASE_ADMIN_PRIVATE_KEY: z.string().min(1),
  STRIPE_SECRET_KEY: z.string().startsWith('sk_'),
  // ... all environment variables validated here
});

export const env = envSchema.parse(process.env);
// This throws at startup if any required variable is missing or invalid.
// No more "undefined is not a string" in production.
```

### Key Flutter Rules
- Strict linting via `very_good_analysis` package
- Clean Architecture pattern (data / domain / presentation separation)
- Riverpod for all state — no setState in presentation layer
- All colours and dimensions from `AppTokens` (never hardcoded)
- `go_router` for all navigation (no `Navigator.push` chains)
- Models use `freezed` for immutability
