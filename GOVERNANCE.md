# Governance

## Project status

Bible is an open public project maintained on GitHub and mirrored on the web.

Canonical repository:

`https://github.com/nicolapitersky/Bible`

Public website:

`https://www.osipov.uk/Bible`

## Project purpose

Bible is intended to be a practical, evolving development handbook for teams, developers, founders, and agencies building with AI coding agents.

The project aims to provide reusable guidance for:

- engineering governance
- AI-assisted development workflows
- agent operating rules
- multi-agent coordination
- review and QA
- safety and environment control
- maintainable project structure
- practical implementation discipline across projects

## Decision model

The project does not currently operate as a committee-governed or voting-governed project.

The maintainer has final discretion over:

- what is in scope
- what is out of scope
- which pull requests are accepted
- how accepted material is edited or reorganised
- the structure of the handbook
- naming, taxonomy, and standards used in the repository
- project positioning and publication strategy

Community input is welcome and encouraged through issues and pull requests.

## Contributions

Public contributions are welcome.

Contributors may propose:

- corrections
- clarifications
- new sections
- workflow improvements
- templates
- examples
- governance patterns
- documentation improvements
- publication and discoverability improvements

The existence of a pull request does not imply that the proposed change matches the intended direction of the project.

## Merge criteria

A contribution is more likely to be accepted if it is:

- practical
- well-scoped
- clearly written
- internally consistent
- useful across more than one narrow scenario
- aligned with the purpose of the project
- realistic for human teams and AI-assisted workflows

A contribution may be declined if it is:

- too vague
- overly promotional
- redundant
- narrowly tied to one tool without clear reason
- structurally inconsistent with the repository
- lower quality than existing guidance
- legally or operationally problematic

## Editorial rights

The maintainer may edit, reformat, reorganise, rename, or partially incorporate submitted contributions before merge.

This includes:

- line edits
- structural edits
- consolidation across files
- splitting or merging sections
- adapting wording for consistency
- rejecting only part of a proposal

## Forks and derivatives

Forks and derivative works are permitted under the repository license.

However, forks and derivative works must not imply that they are the official Bible project or endorsed by the maintainer unless explicit permission has been given.

Where practical, users building on Bible are encouraged to reference the original project:

- `https://github.com/nicolapitersky/Bible`
- `https://www.osipov.uk/Bible`

## Future governance changes

The governance model may evolve over time.

Possible future changes may include:

- additional maintainers
- named reviewers
- domain-specific editors
- formal review areas
- lightweight steering structure

Any such change will be reflected in this file.
