# Security Policy

## Scope

This repository is primarily a public handbook and documentation project.

It may also contain templates, examples, snippets, automation patterns, configuration guidance, or other implementation-related material.

Security reports are welcome where they relate to:

- the repository itself
- the published website for this project
- unsafe or clearly harmful implementation guidance
- exposed secrets or credentials
- supply-chain or dependency concerns in this repository
- materially dangerous workflow or automation recommendations

## How to report a security issue

Please do **not** open public issues for suspected security vulnerabilities or sensitive disclosures.

Report security concerns privately via:

- Email: `support@osipov.uk`
- Website: `https://www.osipov.uk`
- LinkedIn: `https://www.linkedin.com/in/igorosipov/`

If reporting by email, include:

- a clear description of the issue
- where it appears
- steps to reproduce, if applicable
- affected files, URLs, or workflows
- potential impact
- any suggested remediation

## What to expect

Security reports will be reviewed at maintainer discretion.

The project aims to assess reports in good faith and respond proportionately based on severity and practicality.

Because this is a public handbook project rather than a managed service platform, response times and remediation timelines are not guaranteed.

## Responsible disclosure

Please avoid:

- public disclosure before giving reasonable time for review
- publishing sensitive details that create avoidable risk
- sending large unsolicited payloads or destructive test traffic
- attempting to access systems, accounts, or data beyond what is necessary to demonstrate the issue

Good-faith reports intended to improve project safety are appreciated.

## Out of scope

The following are generally out of scope unless they involve a clear security defect in this repository or its published site:

- generic disagreements with architectural opinions
- purely theoretical claims without a plausible exploit path or risk
- vendor-specific model behaviour outside this repository’s control
- issues in third-party tools, platforms, or services not maintained by this project
- requests for guaranteed compliance, certification, or audit status

## No security warranty

This project is provided under the repository license and is made available on an “as is” basis.

Publication of security-related guidance, workflows, templates, or examples does not guarantee that any implementation is safe, complete, compliant, or suitable for a particular environment.

Users remain responsible for reviewing, validating, and safely operating any implementation derived from this project.

## Supported versions

This project is maintained as a continuously evolving public repository rather than through formal version support windows.

In general:

- the current default branch is the primary maintained version
- historical content may remain visible for reference
- older material may not reflect current best practice

## Security-related improvement requests

Contributions that improve safety are welcome, including:

- reducing ambiguity in risky guidance
- clarifying environment or permission boundaries
- improving isolation, review, and validation patterns
- identifying unsafe defaults
- strengthening secure-by-default recommendations
- correcting stale or misleading security guidance

Where practical, please submit non-sensitive improvements by pull request.
